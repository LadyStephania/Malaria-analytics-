Why This Approach

Each district's forecast is simply its own most recent confirmed-case count. Before settling on that, a Random Forest and a Linear Regression were both tried, combining that same case history with rainfall and temperature. Neither came out ahead on real held-out data at any delay setting tried — the weather signal here (see the weak link shown above) wasn't strong enough to add real accuracy on top of a district's own recent pattern. This uses whichever approach actually tested best, not the most sophisticated-sounding one.

Prediction model

The forecast is a persistence model: predicted cases for a district in period t = that district's actual confirmed cases in period t−1. No fitting, no parameters. It's evaluated with a time-based holdout — checked strictly against {{ rf_test_year }}, a full {{ cadence_unit }} never used to establish the pattern. Current result: R² = {{ rf_r2 }}, MAE = ±{{ rf_mae }} ({{ rf_mae_pct }}% of mean actual), n = {{ rf_n_test }}.

What was tried and rejected: a Random Forest Regressor (200 trees, depth-limited) and a Linear Regression, both using rainfall and temperature lagged by the same window selected above (the same offset the correlation panel uses) plus each district's own prior-period case count as a third input. At every delay setting tested (1–3 periods), both scored worse on held-out data than the plain persistence model above — consistent with the weak rainfall/case correlation already shown on this page, which suggests the weather inputs added noise rather than signal on top of an already-strong autoregressive pattern. Persistence is used because it tested best, not because it's the simplest option available.
